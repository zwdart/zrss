# zrss · MyGo 代码架构设计

> 本文面向维护者，说明代码如何分层、状态归谁所有、一次刷新或一次点击如何变成数据库与画面。
> 产品功能与交互规则见 [`功能设计.md`](./功能设计.md)。

---

## 1. 总体结构

### 1.1 一句话概括

zrss 是一个**单进程、无 WebView、全本地存储的 Go 桌面应用**：`main` 只调用 `app.Run`；`internal/app` 持有界面状态并用 MyGo 的 `ui` 包构建原生视图；`internal/feed` 负责抓取与解析；`internal/reader` 把文章 HTML 转成 Markdown；`internal/storage` 封装 SQLite；`internal/opml` 负责订阅列表的导入导出。

### 1.2 依赖方向

```text
main.go
  └── internal/app
        ├── internal/feed
        ├── internal/reader
        ├── internal/storage ─── github.com/egoist/mygo/plugins/sqlite
        └── internal/opml
```

`internal/app` 是唯一的组装层：它把网络结果、数据库行和界面控件接在一起。领域包之间互不依赖：

- `feed` 不认识 UI、数据库和 app；
- `reader` 只处理 HTML → Markdown/纯文本；
- `storage` 只处理 SQL 和行映射；
- `opml` 只处理 XML；
- `app` 可以使用 MyGo 的窗口、菜单、托盘、通知、剪贴板、文件对话框与系统路径。

依赖是单向的：领域包不导入 `app`，因此可以独立测试，也不会把界面细节带进存储层。

### 1.3 分层职责

| 层 | 包/文件 | 职责 | 不该做的事 |
| --- | --- | --- | --- |
| 入口 | `main.go` | 调用 `app.Run()`，把启动错误交给 `log.Fatal`。 | 不持有状态。 |
| 应用层 | `internal/app` | 窗口、三栏视图、侧栏/列表/正文状态、弹层、设置窗口、菜单、托盘、刷新调度、通知、图片缓存、OPML 交互。 | 不直接解析 XML，不拼 SQL，不写 HTML 转换规则。 |
| 抓取领域 | `internal/feed` | HTTP 抓取、条件请求、订阅发现、RSS/RDF/Atom 解析、日期与字符集处理、相对链接解析。 | 不碰数据库和 UI。 |
| 阅读领域 | `internal/reader` | HTML → GFM Markdown、纯文本、摘要、URL 安全过滤。 | 不关心文章来自哪个订阅。 |
| 存储领域 | `internal/storage` | SQLite 连接、schema、文章/订阅/文件夹/设置/搜索历史、FTS、分页、清理。 | 不知道视图长什么样。 |
| 订阅列表 | `internal/opml` | OPML 解析、嵌套文件夹保留、OPML 编码。 | 不直接写数据库。 |
| 平台 | `github.com/egoist/mygo` | 窗口、原生控件、绘制、滚动、菜单、托盘、通知、剪贴板、文件选择器、系统路径。 | — |

### 1.4 关键设计选择

1. **主线程单一状态**：`app` 的界面字段只在主线程读写；后台 goroutine 通过 `a.post` 回到主线程后再修改。这样视图构建不需要为每个字段加锁，也不会读到半更新的列表。
2. **立即式视图**：每帧从头调用 `a.view(c)`，由 MyGo 负责布局、差量绘制和输入命中。应用侧用稳定的 `c.Key` 保持元素身份与动画状态。
3. **SQLite 是唯一事实来源**：已读、星标、订阅元数据、设置和搜索历史都即时落库；内存中的 `a.articles`、`a.feeds` 只是当前视图的快照。
4. **解析在入库前完成**：文章 HTML 只在抓取时转一次 Markdown，并把纯文本一并存入；阅读时不再解析 HTML，搜索直接使用纯文本列。
5. **网络与读取异步**：刷新、分页、图片下载都在后台；结果通过 `post` 回主线程。分页请求会检查范围是否已经变化，避免旧结果覆盖新列表。
6. **领域包可独立测试**：feed 用 `httptest` 和 fixture，reader 用 HTML 片段，storage 用 `:memory:`，opml 用往返编码，app 用内存数据库和假的 HTTP 服务器。

## 4. 启动与生命周期

### 4.1 启动顺序

```text
main.main
└── app.Run
    ├── 构造 app（fetcher、done、collapsed、selected=-1）
    ├── mygo.App.WhenReady(func() {
    │     ├── dataPath("zrss.db")         用户数据目录，创建 0700 目录
    │     ├── storage.Open                PRAGMA + schema + meta.version
    │     ├── loadSettings                读取 settings 表，应用外观
    │     ├── lastRefresh = settings.lastRefreshAt
    │     ├── newImageCache(a.post)
    │     ├── a.md = markdown.Options{OnLink, LoadImage}
    │     ├── reloadSidebar               文件夹、订阅、计数、搜索历史
    │     ├── restoreScope                校验上次范围是否仍存在
    │     ├── reloadArticles              第一页 40 篇
    │     ├── mygo.NewWindow              1240×800，最小 980×620，StateKey "main"
    │     ├── setMenu / applyTray
    │     ├── startScheduler              每 30 秒检查一次
    │     └── 700ms 后首次自动刷新（若开启）
    ├── OnBeforeQuit                      标记 quitting、保存设置、关闭数据库
    ├── OnWillQuit                        关闭 done、销毁托盘
    ├── OnWindowAllClosed                 空实现：关窗不等于退出
    ├── OnActivate                        显示并聚焦主窗口
    └── mygo.App.Run()
```

数据库打不开时显示错误对话框并退出，不会进入半初始化状态。

### 4.2 关闭行为

- 主窗口 `OnClose`：
  - 正在退出：放行；
  - 开启托盘并允许关闭到托盘：阻止默认关闭并隐藏窗口；
  - macOS：无论托盘设置如何都隐藏窗口（平台习惯），由 `Cmd + Q` 退出；
  - 其他情况：调用 `mygo.App.Quit()`。
- `OnBeforeQuit` 会保存上次范围、上次刷新时间和全部设置，再关闭数据库。
- `OnWillQuit` 关闭 `done` 通道，后台刷新循环在下一个订阅前退出；托盘图标被销毁。
- 设置窗口关闭后引用置空，下次打开重新创建。

### 4.3 窗口状态

主窗口使用 MyGo 的 `StateKey: "main"` 记忆尺寸/位置；设置窗口使用 `"settings"`。主窗口最小尺寸保证三栏仍然可用；设置窗口禁止最大化并隐藏菜单栏。

## 5. 并发模型

### 5.1 主线程

`app` 的以下字段只在主线程读写：

- 窗口、设置窗口、托盘引用；
- `settings`、`folders`、`feeds`、`counts`、`collapsed`；
- `scope`、`scopeTitle`、`articles`、`selected`、`current`、`listState`、`readerScroll`；
- 搜索框、搜索历史、定时器；
- 覆盖层状态、提示文字、刷新标志。

视图构建、菜单回调、托盘回调、窗口事件都在主线程触发。

### 5.2 后台 goroutine 与回主线程

| 来源 | 工作 | 回到主线程 |
| --- | --- | --- |
| 调度器 | 每 30 秒检查是否到期 | `a.post` 中判断并调用 `refreshAll` |
| 全量刷新 | 顺序抓取每个订阅、写库、清理 | 一次性 `post` 更新计数、列表、提示、通知 |
| 单个刷新 | 抓取一个订阅、写库 | `post` 重载侧栏和列表 |
| 分页 | 查询下一页 | `post` 检查范围未变后追加 |
| 搜索 | 220 ms 防抖后查询 | `post` 执行过滤 |
| 图片缓存 | 下载、解码 | 成功后 `post` 触发重绘 |
| OPML | 读文件、解析、批量添加 | `post` 重载并提示 |

`a.post` 的实现：

```go
func (a *app) post(fn func()) {
    if a.quitting.Load() {
        return
    }
    if a.win == nil { // 启动早期或测试
        fn()
        a.redraw()
        return
    }
    a.win.Update(func() {
        fn()
        a.redraw()
    })
}
```

- 窗口出现前直接执行，让启动数据加载和测试不必等待事件循环。
- 窗口出现后交给 `Window.Update`，保证回调在主线程。
- `quitting` 使用 `atomic.Bool`，因为后台 goroutine 会在退出的同时尝试回来；其余界面字段仍只由主线程访问。
- 后台任务在启动前捕获需要的快照（例如订阅列表和保留数量），避免读取主线程正在修改的字段。

### 5.3 过期结果的防护

- `loadMore` 捕获发起时的 `scope`；回调时若 `a.scope` 已变，直接丢弃结果。
- `refreshing` 防止同时启动两轮全量刷新。
- 后台刷新在 `done` 关闭后尽快退出。
- 图片缓存以 URL 为键，用互斥锁保护下载状态；同一 URL 的并发请求只启动一次下载。

### 5.4 SQLite 并发

MyGo 的 SQLite 插件序列化操作，`Store` 可以被多个 goroutine 使用。数据库启用：

- `foreign_keys = ON`：删除订阅级联删除文章；
- `journal_mode = WAL`：读写并行更顺畅；
- `synchronous = NORMAL`：本地阅读器的性能/安全折中；
- `busy_timeout = 5s`。

批量写入使用事务，每 200 条一组，避免超长事务和单条语句开销。

## 6. 数据模型

### 6.1 表

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `meta` | `key`, `value` | 当前 `version = 2`。 |
| `folders` | `id`, `parent_id`, `name COLLATE NOCASE`, `sort` | 最多三级的文件夹树；`parent_id = 0` 表示根文件夹；`UNIQUE(parent_id, name)`，不同父级可以同名。 |
| `feeds` | `id`, `url UNIQUE`, `site_url`, `title`, `description`, `icon_url`, `folder_id`, `sort`, `custom_title`, `etag`, `last_modified`, `last_fetch`, `last_error`, `created_at` | 订阅及抓取状态。 |
| `articles` | `id`, `feed_id`, `guid`, `url`, `title`, `author`, `summary`, `content`, `plain`, `image_url`, `published`, `fetched`, `read`, `starred` | `UNIQUE(feed_id, guid)`；`feed_id` 外键级联删除。 |
| `articles_fts` | `title`, `summary`, `plain` | FTS5 外部内容表，`content='articles'`，`tokenize='trigram'`。 |
| `settings` | `key`, `value` | 全部设置与上次范围/刷新时间。 |
| `searches` | `query COLLATE NOCASE PRIMARY KEY`, `used_at` | 最近搜索，最多 8 条。 |

索引：

- `folders(parent_id, name)` 唯一索引；
- `folders(parent_id, sort)`；
- `feeds(folder_id, sort)`；
- `articles(published DESC, id DESC)`；
- `articles(feed_id, published DESC, id DESC)`；
- `articles(read, published DESC, id DESC)`；
- `articles(starred, published DESC, id DESC)`。

FTS 由三个触发器维护：插入、删除、标题/摘要/纯文本更新。`content` 与 `plain` 存 Markdown 和纯文本；`summary` 是列表用的短文本。

schema 版本存放在 `meta.version`。`init` 发现 v1 数据库时，会为 `folders` 补 `parent_id`、移除旧的全局唯一索引，并建立 `(parent_id, name)` 唯一索引，同时保留原有文件夹 ID 和订阅的 `folder_id`；迁移后的旧文件夹都成为根文件夹。

### 6.2 文章身份与 upsert

`guidKey` 依次使用 GUID、链接、`sha1(title + NUL + content + NUL + published)`。这让没有 GUID 的订阅也能稳定去重。

`UpsertArticles` 使用：

```sql
INSERT INTO articles(...) VALUES(...)
ON CONFLICT(feed_id, guid) DO UPDATE SET ...
WHERE 任意一个可更新字段与 excluded 不同
```

效果：

- 重复抓取不产生新行；
- 正文有变化时更新，无变化时连写入都跳过；
- `read`、`starred`、`fetched` 不在更新列中，因此本地状态保留；
- 用刷新前后的 `COUNT(*)` 差计算新增数量。

### 6.3 范围查询

`Scope` 是列表的唯一输入：

| Kind | SQL |
| --- | --- |
| `all` / 空 | `1 = 1` |
| `unread` | `a.read = 0` |
| `starred` | `a.starred = 1` |
| `today` | `a.published >= 本地当天 00:00` |
| `feed` | `a.feed_id = ?` |
| `folder` | `a.feed_id IN (SELECT id FROM feeds WHERE folder_id IN (<递归子树>))` |
| `search` | FTS 或 `LIKE` |

列表、计数、全部标为已读共用 `scopeWhere`，保证「看到的」和「标记的」是同一批文章。文件夹范围先用递归 CTE 求出整棵子树，再把其中的订阅作为过滤条件。

### 6.4 搜索

`searchWhere` 把查询按空白拆词：

- 每个词至少 3 个字符：使用 FTS5 trigram，词用双引号包裹并以 `AND` 连接；
- 任一词少于 3 个字符：每个词分别匹配 `title/summary/plain LIKE '%词%' ESCAPE '\'`，再用 `AND` 连接；
- 空查询返回 `0 = 1`。

双引号内的内容会转义双引号，`LIKE` 会转义 `\`、`%`、`_`。

### 6.5 清理

`Prune(keepPerFeed)`：

```sql
DELETE FROM articles
WHERE read = 1 AND starred = 0 AND id NOT IN (
  SELECT id FROM (
    SELECT id, ROW_NUMBER() OVER (
      PARTITION BY feed_id ORDER BY published DESC, id DESC
    ) AS rn FROM articles
  ) WHERE rn <= ?
)
```

即每个订阅最新 N 篇之外，只删除「已读且未星标」的文章。未读和星标文章不参与删除。

## 7. 抓取、解析与阅读流水线

### 7.1 一次全量刷新

```text
refreshAll(manual)
├── 检查 store / quitting / refreshing / 订阅数量
├── 快照 feeds 与 keepArticles
└── goroutine
    ├── 对每个 feed：refreshFeed
    │   ├── feed.total == 0 → 不带 ETag/Last-Modified 强制下载全文
    │   ├── Fetcher.Fetch(url, etag, lastModified)
    │   │   ├── 200 → 解析 Document
    │   │   ├── 304 → NotModified
    │   │   └── 其他/错误 → error
    │   ├── 失败：UpdateFeed(last_error, last_fetch)
    │   ├── 304：只更新 last_fetch 与 ETag/Last-Modified
    │   ├── 200：UpdateFeed(title/site/description/icon/etag/last_fetch)
    │   └── UpsertArticles(articleInputs(doc, finalURL))
    │       └── 失败：清空 ETag/Last-Modified，下次强制重新下载
    ├── Prune(keepArticles)
    └── post
        ├── refreshing=false、lastRefresh=now、保存设置
        ├── 重载侧栏与列表
        └── 提示 / 通知
```

`UpdateFeed` 的 SQL 使用：

```sql
title = CASE WHEN custom_title = 1 THEN title ELSE ? END
```

因此用户重命名过的订阅不会被下一次抓取覆盖。

### 7.2 解析

`feed.Parse` 只看根元素：

- `<rss>` → RSS 文档；
- `<rdf:RDF>` → RDF 文档，共用 RSS 映射；
- `<feed>` → Atom 文档；
- 其他 → `unsupported document root`。

XML 解码器：

- `Strict = false`：容忍不规范的现实订阅；
- `Entity = xml.HTMLEntity`：识别 `&nbsp;` 等 HTML 实体；
- `CharsetReader = charset.NewReaderLabel`：处理 XML 声明给出的字符集；
- 抓取时如果声明没有写编码，先按 HTTP `Content-Type` 的 charset 转成 UTF-8；
- 去除 UTF-8 BOM。

URL 解析：

- 协议相对 URL 补当前页面协议；
- 以最终响应 URL 为 base 解析相对路径；
- 只保留 `http`/`https`；
- 没有 base 时保留原始相对值（订阅发现的上层会再解析）。

### 7.3 文章入库前的转换

`articleInputs` 对每个 item：

1. 以最终订阅 URL 为 base；若 item 有链接，再以链接为 base，保证正文里的相对链接指向文章页面。
2. `reader.ToMarkdown(content, base)`；为空则用 `summary`。
3. `reader.PlainText(content)`；为空则用 `summary`。
4. `reader.Summary(summary, 240)`；为空则用正文生成摘要。
5. 标题为空时写「无标题」。
6. 保存 GUID、URL、标题、作者、摘要、Markdown、纯文本、图片 URL、发布时间。

`reader` 会：

- 丢弃 `script`、`style`、`noscript`、隐藏节点、注释；
- 把标题、段落、列表、引用、代码、表格、图片、链接映射为 Markdown/GFM；
- 解析相对链接与图片；
- 过滤 `javascript:` 等非 http(s) 链接；
- `PlainText` 不生成标记，只保留可读文本；
- `Summary` 按 rune 截断，英文尽量退到空格，中文按字符边界。

### 7.4 订阅发现

添加订阅时 `resolveFeed` 依次尝试：

1. 用户给出的地址本身；
2. `Fetcher.Discover` 抓取 HTML，先返回 `link rel=alternate` 的 RSS/Atom/RDF/XML 链接；
3. 同一页面里路径以 `.rss`、`.xml`、`.atom` 结尾的 `<a>`，接在链接之后；
4. `feed.Candidates` 的常见路径。

每个候选只尝试一次（`seen` 集合去重），成功解析即返回。`Discover` 本身也会先判断响应是否已经是订阅；是则直接返回最终 URL。

### 7.5 网络与代理

`fetch.go` 的默认 transport 使用 `proxyFromSettings`，而不是只依赖 Go 默认的 `ProxyFromEnvironment`：

1. `http.ProxyFromEnvironment` 处理 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 及小写变体；
2. 没有环境变量时，Windows 读取 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` 与 `ProxyServer`；`ProxyServer` 支持 `host:port`、`http=...;https=...` 和 `socks=...`，SOCKS 会转成 `socks5://`；
3. `localhost`、回环 IP 直接返回无代理，保证本地测试服务器可用；
4. 非 Windows 平台的 `systemProxyURL` 返回 nil。

添加订阅失败时，`resolveFeed` 会把最后一次请求错误带回界面，提示里同时包含「没有找到订阅源」和具体网络错误，便于区分代理/网络故障与站点没有订阅。

## 12. 已知边界与后续方向

### 12.1 当前边界

| 边界 | 影响 |
| --- | --- |
| 全量刷新是顺序的 | 订阅很多时总耗时约等于各订阅耗时之和；好处是请求节奏平稳、实现简单。 |
| 图片缓存只在内存 | 重启后重新下载；长时间运行且浏览大量图片时内存会增长，没有 LRU 上限。 |
| 文章只来自订阅内容 | 不抓取原文网页，不做 Readability 正文提取；订阅只给摘要时，阅读区也只有摘要。 |
| 不播放媒体 | enclosure 与播客链接会被解析，但没有音频/视频播放器。 |
| FTS trigram 对短词退化 | 少于 3 个字符的词使用 `LIKE` 扫描，文章极多时比 FTS 慢。 |
| 文件夹最多三级 | 更深的 OPML 层级会在导入时并入第三级；侧栏不提供第四级。 |
| 只有 Windows 读系统代理 | 其他平台依赖 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`；本地代理工具若只配置系统设置，需要另外设置环境变量。 |
| 无自动更新 | 新版本需要用户手动下载安装。 |
| 无同步 | 多设备需要各自维护数据库，或通过 OPML 迁移订阅。 |
| 无全文高亮 | 搜索只过滤列表，不在正文中标记命中词。 |

### 12.2 可以沿用的扩展点

- **并行刷新**：把 `refreshAll` 的串行循环改为有上限的 worker pool，同时保留每个订阅的独立错误。
- **图片磁盘缓存**：在 `imageCache` 外增加按 URL 哈希的缓存目录，并设置总大小/淘汰策略。
- **正文提取**：在 `refreshFeed` 中为只有摘要的文章请求原文并用 reader 提取正文，需遵守站点协议与超时。
- **媒体播放**：`feed.Item` 已有 `EnclosureURL`，可以接入 MyGo 的 `audio` 包，增加播客播放条。
- **更新**：MyGo 的 updater 插件已可用，补齐签名密钥与发布清单即可。
- **高亮与定位**：搜索摘要可保存命中片段；`storage.Neighbours` 已提供相邻文章查询，可用于更复杂的键盘导航或阅读历史。

## 13. 维护约定

- Go 注释使用英文，界面文案使用中文。
- 新增字段先想清楚它属于 `app` 的临时视图状态，还是应该进入 SQLite；持久化状态一律走 `storage`。
- 新增网络行为必须设置超时、大小上限与 User-Agent，并考虑条件请求。
- 新增界面交互优先使用 MyGo 的 `ui` 原语与 `c.Key`，不要手写平台判断。
- 修改 schema 时提升 `schemaVersion` 并补迁移；不要依赖用户删库重建。
- 修改数据库行为时补行为测试；不要用界面文案断言替代状态断言。
- 提交前运行 `go test ./...`、`go vet ./...` 和 `go build ./...`。
