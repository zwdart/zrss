# zrss · MyGo 功能设计说明

> 本文从产品与用户视角说明 zrss 提供什么、怎么用、在什么情况下表现如何。
> 实现层面的包结构、线程模型和数据流见 [`代码架构设计.md`](./代码架构设计.md)。

---

## 1. 产品概述

### 1.1 定位

zrss 是一个本地优先的桌面 RSS 阅读器。它用 Go 与 [MyGo](https://github.com/egoist/mygo) 的原生 UI 框架编写，界面由系统原生绘制，不使用 WebView，因此启动快、内存占用低，也能自然地融入 macOS、Windows 与 Linux 的窗口、菜单栏和通知区域。

目标不是做一个在线的内容平台，而是把「读订阅」这件事做顺：

- 打开就能继续上次浏览的位置；
- 添加一个网址后，应用自己找到它的 RSS、RDF 或 Atom 订阅源；
- 未读、星标、今天和文件夹都在一个窗口里；
- 已读状态、星标、订阅和设置都在本机，退出、重启、断网都不会丢；
- 阅读界面只留下文字、图片和必要的元数据，不加载网页脚本。

### 1.2 设计原则

| 原则 | 具体表现 |
| --- | --- |
| 阅读优先 | 三栏布局中正文占据最大空间；选中文章立即进入阅读，`J` / `K` 可以连续翻读。 |
| 一屏之内 | 订阅、列表、正文同屏；搜索、设置、添加订阅都以轻量弹层或独立设置窗口完成。 |
| 本地优先 | 订阅、文章、已读/星标、搜索历史、设置全部在一个 SQLite 文件里，不依赖账号或云服务。 |
| 渐进呈现 | 列表分页加载；文章图片异步下载；刷新在后台进行，界面显示进度而不阻塞。 |
| 少打扰 | 只有窗口在后台且开启通知时才提示新文章；刷新失败只在对应订阅旁显示警告。 |
| 可恢复 | 上次的侧栏位置、窗口大小、刷新时间和设置都会恢复。 |
| 可迁移 | 订阅可以通过 OPML 导入和导出，数据库也可以直接备份。 |

### 1.3 技术形态

- 单主窗口 + 独立的「设置」窗口。
- 主窗口采用「订阅侧栏 + 文章列表 + 正文阅读区」的三段式布局。
- 无 WebView；控件、滚动、图片、Markdown 渲染、菜单和托盘都由 MyGo 原生绘制或调用系统能力。
- 订阅、文章、设置等业务数据全部写入 SQLite；没有业务 JSON 配置文件，也没有服务端。

## 2. 用户与典型场景

| 场景 | 用户动作 | 客户端响应 |
| --- | --- | --- |
| 第一次使用 | 打开应用，点击「添加订阅」 | 输入博客首页或订阅地址；若输入的是网页，自动发现其中的订阅链接或尝试常见路径。 |
| 每天早晨 | 启动应用 | 恢复上次的侧栏位置；按设置的间隔在后台刷新，未读数出现在侧栏。 |
| 快速浏览 | 按 `J` 连续向下 | 列表选中项前进，正文切换，文章按设置自动标为已读；滚动到列表底部时加载下一页。 |
| 想稍后再读 | 按 `S` 或点星标按钮 | 文章进入「星标」，侧栏星标计数增加。 |
| 找一篇旧文章 | 按 `Cmd/Ctrl + F` 输入关键词 | 停止输入约 220 ms 后即时过滤；回车把关键词写入最近搜索。 |
| 换电脑或换阅读器 | 文件菜单导出 OPML | 生成包含文件夹层级的 OPML 文件；在别处导入后订阅关系保留。 |
| 离开电脑 | 关闭窗口 | 若开启托盘，窗口隐藏、刷新继续；点托盘图标或 Dock 图标重新打开。 |
| 网络不稳定 | 定时刷新 | 失败的订阅保留旧文章并显示警告图标；其他订阅照常更新。 |
| 磁盘空间有限 | 设置「保存的文章数量」 | 下次刷新后清理超出范围的已读、未星标文章；未读与星标永远保留。 |

## 3. 信息架构

### 3.1 窗口

| 窗口 | 说明 |
| --- | --- |
| 主窗口 | 侧栏、文章列表、正文阅读区；添加订阅、重命名、确认删除以覆盖层出现。 |
| 设置窗口 | 独立窗口，`Cmd/Ctrl + ,` 打开；关闭后不影响主窗口。 |
| 托盘 | Windows / Linux 的通知区域图标，macOS 的菜单栏图标；可打开窗口、刷新、全部标为已读、进入设置或退出。 |

主窗口使用系统标题栏，不绘制自绘标题栏。这样三平台的窗口按钮、贴边、全屏和辅助功能行为都由系统负责。

### 3.2 侧栏

侧栏从上到下分为四部分：

1. **品牌与刷新**：`zrss` 标识、当前刷新状态入口。
2. **搜索框**：即时搜索；为空且获得焦点时显示最近搜索。
3. **导航**：
   - 智能视图：全部文章、未读、星标、今天；
   - 文件夹：最多三级，像文件目录一样逐级折叠，显示文件夹内（含子文件夹）的未读数；首次启动会创建「默认」文件夹；
   - 订阅：直接显示在所属文件夹下；所有订阅都必须位于某个文件夹中，不再有「顶层 / 不放入文件夹」的选项。
4. **底部操作**：添加订阅、导入 OPML、导出 OPML、设置。

### 3.3 文章列表

- 标题显示当前范围（智能视图名、文件夹名、订阅名或搜索词）。
- 副标题始终显示当前范围的文章总数（例如「共 20 篇文章」）；分页还有更多时再显示「已加载 N 篇」；另外显示上次刷新时间，刷新时显示旋转指示。
- 每条文章固定三行：标题、单行摘要，以及最后的「时间 · 订阅名」行；时间在前且不截断，订阅名在空间不足时收缩。所有文字从左侧开始排列，未读圆点、星标和可选缩略图同样在这一区域内展示。
- 右键菜单：标为已读/未读、加星标/取消星标、打开原网页、复制链接。
- 触底自动加载下一页，每页 40 篇。
- 空列表按范围给出不同提示；加载失败时给出「重试」。

### 3.4 正文区

- 顶部：订阅名、星标、已读/未读、复制链接、打开原网页。
- 标题下方：发布时间、订阅名、作者、预计阅读时间。
- 正文：HTML 转成的 Markdown，支持标题、列表、引用、代码块、表格、图片和链接；最大宽度 780 px，居中显示。
- 底部：在浏览器中打开原文，并显示原文域名。
- 没有选中文章时显示引导文案，而不是空白。

### 3.5 导航与状态

- 侧栏选择是一个 `Scope`：全部、未读、星标、今天、文件夹、订阅或搜索。
- 切换范围会重新加载第一页，并清空当前选中文章。
- 在同一范围内刷新或标记已读时，尽量保留当前文章的选中位置。
- 搜索是临时访问：清除搜索后回到进入搜索前的范围。
- 上次的非搜索范围写入设置，下次启动恢复；若对应的订阅或文件夹已删除，则回到「全部文章」。

## 4. 功能详述

### 4.1 订阅管理

#### 添加订阅

入口：

- 侧栏底部 `+`；
- 文件菜单「添加订阅…」；
- 快捷键 `Cmd/Ctrl + N`；
- 空列表中的「添加订阅」。

流程：

1. 输入网址；没有协议时补 `https://`。
2. 先直接请求该地址。若响应能解析成订阅，直接使用。
3. 若是一个 HTML 页面，读取 `<link rel="alternate">` 中类型为 RSS、Atom、RDF 或 XML 的链接，逐个尝试。
4. 若仍没有结果，尝试站点根路径下的 `/feed`、`/rss`、`/rss.xml`、`/feed.xml`、`/atom.xml`、`/index.xml`、`/feeds/posts/default` 等常见位置。
5. 添加成功后立即抓取一次，让列表马上有内容；提示会说明新收到的文章数量，若抓取失败则明确提示「已添加订阅，但抓取文章失败」并附带网络错误。
6. 若该 URL 已经订阅，选中已有订阅并提示「已经订阅过了」。
7. 找不到订阅时提示「没有找到这个地址的订阅源」，并附带最后一次网络错误（例如代理不可用、域名无法解析），方便区分「没有订阅源」和「网络访问不了」；不创建空记录。

添加对话框只列出文件夹，默认选中「默认」文件夹；从文件夹视图打开时会预选该文件夹。没有「不放入文件夹」选项。

#### 文件夹

- 侧栏「文件夹」旁的 `+` 新建根文件夹；右键文件夹选择「新建子文件夹」最多建到第三级，第四级会被拒绝。
- 首次启动自动创建「默认」文件夹；旧版本中位于顶层的订阅会在启动时自动移入「默认」。
- 「默认」文件夹不能删除；如果它被其他途径删掉，下次启动或添加订阅时会重新创建。
- 名称去除首尾空白，空名称不创建；同一父级下不区分大小写唯一，同名时复用已有文件夹并返回其 ID。
- 不同父级下可以存在同名文件夹，例如顶层「Go」和「技术 / Go」是两个文件夹。
- 右键文件夹可以新建子文件夹、在文件夹内添加订阅、重命名、移动到其他文件夹或删除。
- 移动文件夹会检查环和深度：不能移到自己或自己的子孙下面，移动后整棵树不能超过三级，目标父级下也不能有同名文件夹。
- 删除文件夹会删除它下面的子文件夹；子树中的所有订阅上移到被删除文件夹的上一级（删除根文件夹时进入「默认」），文章全部保留。
- 点击文件夹范围会包含它下面所有层级的订阅文章。
- 订阅右键菜单「移动到文件夹」可以在任意层级文件夹之间移动，不再提供移动到顶层。

#### 订阅

- 右键订阅可以：刷新这个订阅、全部标为已读、移动到文件夹、重命名、打开网站、取消订阅。
- 重命名只改变显示名，并写入 `custom_title`；后续抓取发现的新标题不会覆盖用户改过的名字。
- 取消订阅会删除该订阅及其全部文章，操作前二次确认。
- 订阅行显示未读数；抓取失败时显示红色警告图标，悬停可看错误信息。

### 4.2 抓取与更新

#### 支持的格式

| 格式 | 识别方式 | 主要字段 |
| --- | --- | --- |
| RSS 0.91 / 2.0 | 根元素 `<rss>` | `channel.title/link/description/language/image`，`item.title/link/description/content:encoded/pubDate/author/dc:creator/guid/enclosure/media:*` |
| RSS 1.0（RDF） | 根元素 `<rdf:RDF>` | 与 RSS 共用 item/channel 映射，支持 `rdf:about`、`dc:date`、`dc:creator` |
| Atom 1.0 / 0.3 | 根元素 `<feed>` | `title/subtitle/tagline/icon/logo/author/link`，`entry.id/title/summary/content/published/issued/updated/modified/author/link rel=enclosure` |

解析细节：

- 使用宽松 XML 解码器，接受现实中常见的不规范标记和 HTML 实体。
- 根据 XML 声明处理非 UTF-8 字符集；声明没有写编码时使用 `Content-Type` 的 charset，并去除 UTF-8 BOM。
- 相对链接按最终响应 URL 解析；只保留 `http` 与 `https`。
- 正文优先使用 `content:encoded` / Atom `content`，缺失时回退到 `description` / `summary`。
- 标题和摘要先转为纯文本；正文保留 HTML，交给 `internal/reader` 转成 Markdown。
- 文章缩略图来自 `media:thumbnail`、Atom `<thumbnail>` 或图片类型的 `media:content`；订阅图标来自 RSS `<image>` 或 Atom `icon` / `logo`。
- 发布日期依次尝试 `pubDate`、`dc:date`、`published`、`issued`、`updated`、`modified`；无法解析时按零时间处理，列表仍会显示。

#### 请求策略

- 默认 User-Agent 为 `zrss/0.1`，Accept 同时声明 RSS、Atom、RDF、XML 与 HTML。
- 代理选择顺序：先读 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 等环境变量；没有环境变量时，Windows 读取「Internet 选项」中的系统代理（遵循 `ProxyEnable`，支持 `host:port`、按协议配置和 SOCKS）。其他平台只使用环境变量。
- `localhost`、`127.0.0.1` 与 `::1` 始终直连，避免本地测试或本地服务被代理拦截。
- 超时 25 秒，最多 10 次重定向。
- 单个订阅响应上限 12 MiB；发现订阅的 HTML 页面上限 4 MiB。
- 保存 `ETag` 与 `Last-Modified`，之后以 `If-None-Match` / `If-Modified-Since` 发起条件请求。服务器返回 304 时只更新抓取时间，不重新解析。
- 如果数据库里还没有该订阅的任何文章，就不发送条件请求，直接下载全文；这样即使旧版本遗留了 ETag 而文章写入失败，下一次刷新也能把文章补回来。文章写入失败时同时清空 ETag 与 `Last-Modified`，避免 304 再次挡住重新下载。
- 抓取失败会把错误写入订阅的 `last_error`，保留旧文章与旧的 ETag；下一次刷新继续尝试。

#### 文章去重

同一订阅内，文章键依次取：

1. 非空 GUID；
2. 非空链接；
3. 标题、正文与发布时间的 SHA-1 摘要。

抓取结果以 `(feed_id, guid)` 唯一约束写入。重复文章会更新正文、标题、作者、摘要、图片和时间，但保留本地已读与星标状态；只有数据库中确实新增了行，才计入「收到 N 篇新文章」。

#### 刷新时机

- **手动**：侧栏刷新按钮、列表刷新按钮、菜单、托盘、设置窗口。
- **单个订阅**：订阅右键菜单。
- **定时**：启动后若设置了自动刷新，约 700 ms 后先刷新一次；之后每 30 秒检查一次是否到期。修改刷新间隔无需重启。
- 刷新期间再次手动刷新只提示「正在刷新…」，不会并发启动第二轮全局刷新。

#### 通知

刷新发现新文章时：

- 只有开启「新文章通知」、系统支持通知、窗口存在且不在前台时才发送；
- 通知内容是「收到 N 篇新文章」，点击通知打开主窗口；
- 没有新文章时不发送通知。

#### 清理

设置中的「保存的文章数量」控制每个订阅保留多少篇最近的文章：

- 可选 100、200、500、1000 或全部；
- 每次全局刷新结束后执行；
- 只删除「已读且未星标」且排在该订阅最新 N 篇之外的文章；
- 未读与星标文章不受数量限制，永远不会被自动清理。

### 4.3 阅读与列表

#### 范围与分页

- 智能视图：全部、未读、星标、今天（今天从本地时间 00:00 起算）。
- 文件夹范围是该文件夹下所有订阅的文章。
- 列表按发布时间倒序、ID 倒序排列；每页 40 篇。
- 列表滚动到末尾时自动取下一页；如果切换了范围，旧请求的结果会被丢弃。

#### 选中与已读

- 点击文章行或按 `J` / `K` / 方向键选中文章。
- 默认「打开即已读」：选中未读文章时立即写入 `read = 1`，侧栏计数同步更新。可以在设置中关闭。
- `U` 切换当前文章的已读状态；右键单篇也可以切换。
- `M` 或列表标题旁的「全部标为已读」会把当前范围内的未读文章全部标为已读。
- 读过的文章会保留在当前列表里，避免阅读时列表跳动；切换范围或刷新后，它会从「未读」中消失。

#### 星标

- `S`、正文顶部的星标按钮或右键菜单切换星标。
- 星标文章出现在「星标」视图，侧栏显示数量。
- 取消订阅会连星标文章一起删除。

#### 打开与复制

- `Cmd/Ctrl + O`、正文按钮或右键菜单在系统浏览器中打开原文。
- 若文章没有链接，则回退到订阅的站点地址；两者都没有时提示「这篇文章没有链接」。
- `Cmd/Ctrl + C` 的普通复制由输入框和正文选择处理；「复制文章链接」在编辑菜单、右键菜单或正文按钮中。
- 复制成功用轻提示确认。

#### 图片

- 文章正文中的图片由 Markdown 视图按需请求，经应用内缓存加载。
- 列表缩略图与订阅图标也走同一个缓存；下载中的图标先显示订阅名首字或色块。
- 支持 PNG、JPEG、GIF、WebP、BMP 与 SVG，单张上限 8 MiB，超时 15 秒。
- 图片请求不阻塞界面绘制；加载完成后主线程重绘。

#### 阅读辅助

- 正文字号可在 12–24 px 之间调整；设置窗口提供小、标准、大、特大、超大五档，菜单和 `Cmd/Ctrl + =` / `-` 按 1 px 调整。
- 预计阅读时间按纯文本字符数估算，约 350 字/分钟，最少 1 分钟。
- 时间显示为「刚刚」「N 分钟前」「N 小时前」「昨天」「N 天前」，超过一周显示日期。

### 4.4 搜索

- 搜索框位于侧栏顶部，`Cmd/Ctrl + F` 聚焦。
- 输入后等待 220 ms 再执行，避免每个按键都查询数据库。
- 查询词按空白拆成多个词，所有词都必须匹配。
- 每个词至少 3 个字符时使用 FTS5 trigram 索引；有更短的词时退回 `LIKE` 扫描，两条路径匹配相同的列：标题、摘要、纯文本正文。
- 搜索结果是临时范围，标题显示「搜索『关键词』」；清除搜索后回到之前的范围。
- 回车提交时写入最近搜索；重复关键词更新时间并去重，只保留最近 8 条。
- 搜索框为空且获得焦点时显示最近搜索，可以点选，也可以一键清空。
- 搜索历史同样存储在 SQLite 中，清空后不可恢复。

### 4.5 OPML 导入与导出

#### 导入

- 入口：文件菜单、侧栏底部、设置窗口；快捷键 `Cmd/Ctrl + Shift + I`。
- 文件选择器接受 `.opml` 与 `.xml`。
- 支持标准 OPML 2.0；嵌套文件夹按 outline 的包含关系还原成树，最多保留三级。
- outline 的订阅地址读取 `xmlUrl`，并兼容 `xmlurl` 写法；标题读取 `text`，回退 `title`；站点地址读取 `htmlUrl`，并兼容 `htmlurl`。
- 没有订阅地址但有子节点的 outline 视为文件夹；没有名称的 outline 不创建文件夹，其中的订阅挂到当前父级。
- 第四级及更深的文件夹不会创建，其中的订阅并入第三级；订阅本身不会丢失。
- 导入时跳过已存在的订阅 URL；同一父级下的同名文件夹复用。
- 顶层订阅导入到「默认」文件夹；没有文件夹归属的订阅也进入「默认」。
- 导入完成后刷新全部订阅，并提示新增数量。

#### 导出

- 入口：文件菜单、侧栏底部、设置窗口；快捷键 `Cmd/Ctrl + Shift + E`。
- 默认文件名 `zrss-subscriptions.opml`，位于用户主目录；没有扩展名时自动补 `.opml`。
- 顶层订阅先写入，然后按侧栏顺序递归写入文件夹及其子文件夹、订阅。
- 输出为缩进良好的 OPML 2.0，嵌套层级与侧栏一致，方便阅读和版本控制。

### 4.7 托盘与系统集成

#### 托盘菜单

- 打开 zrss；
- 刷新全部订阅；
- 全部标为已读；
- 设置…；
- 退出 zrss。

点击托盘图标本身打开主窗口。

#### 关闭行为

- macOS：关闭主窗口总是隐藏窗口，应用继续运行；使用 `Cmd + Q` 或菜单退出。
- Windows / Linux：若开启「显示托盘图标」和「关闭窗口时留在托盘」，关闭按钮隐藏窗口；否则退出应用。

- macOS 使用黑色模板图标，由系统按菜单栏明暗着色；Windows / Linux 使用彩色 RSS 图标。
- macOS 的「关于」「服务」「隐藏」「退出」使用系统角色；其他平台显示对应的应用菜单。
- Linux 以原生 UI 运行，不依赖 WebKitGTK，只依赖 GTK 3。
- 所有平台都使用系统标题栏、系统文件选择器与系统浏览器。

### 4.10 数据与隐私

- 业务数据唯一持久化存储是 `zrss.db`（SQLite，WAL 模式）；窗口位置和大小由 MyGo 另存在用户数据目录的 `window-state.json` 中。
- 数据目录由 MyGo 的用户数据路径决定：
  - macOS：`~/Library/Application Support/zrss/`
  - Windows：`%AppData%\zrss\`
  - Linux：`$XDG_CONFIG_HOME/zrss/`（默认 `~/.config/zrss/`）
- 数据库内包含订阅、文件夹、文章正文与纯文本、已读/星标、ETag、设置和搜索历史。
- OPML 是唯一的批量导出格式；没有账号、云同步、遥测或崩溃上报。
- 网络请求只发生在：刷新订阅、发现订阅、下载文章图片/订阅图标、在浏览器中打开链接。
- 用户可以选择不显示托盘、关闭通知、把自动刷新设为手动。

### 4.11 性能与规模

- 本地查询不经过网络，列表分页与 FTS 索引保证数千篇文章仍可即时滚动。
- 列表使用虚拟化 `ui.List`，只绘制可见行。
- 正文 HTML 在入库时转成 Markdown，阅读时不再解析 HTML。
- 图片异步加载并缓存于内存；同一 URL 只下载一次。
- 清理策略避免数据库无限增长；`VACUUM` 可以回收删除后的空间。

### 4.12 非目标

- 不做账号、云同步、在线推荐或社交功能。
- 不做移动端或 Web 端。
- 不内嵌浏览器，不执行文章里的脚本，不抓取订阅之外的网页正文。
- 不播放播客音频或视频；enclosure 会被解析，但当前版本没有媒体播放器。
- 不提供自动更新；发布包需要手动下载安装。

## 5. 跨平台与可访问性

- 所有交互控件都带辅助功能标签；列表行使用文章标题作为标签。
- 键盘可以完成添加订阅之外的日常阅读：导航、已读、星标、搜索、刷新、打开原文。
- 颜色对比度按浅色/深色主题分别调整；强调色只用于强调，不承担唯一的信息表达。
- 触控板与鼠标滚轮使用系统滚动行为；列表和正文分别保存滚动状态。

## 6. 验收关注点

以下行为是回归测试的重点，而不是界面文案：

1. RSS 2.0、RSS 1.0/RDF、Atom 1.0 与 Atom 0.3 都能解析出标题、链接、正文、作者和时间。
2. 条件请求第二次返回 304 时不会重复写入文章，也不会丢失已读/星标。
3. 同一 GUID 的更新保留本地状态；新增文章才计入新文章数量。
4. 搜索能同时匹配标题、摘要和正文；短词走 `LIKE` 也能找到结果。
5. 切换范围、搜索、清除搜索后列表内容正确，且不破坏保存的上次范围。
6. 选中文章按设置标记已读，侧栏未读数同步；星标与取消星标同步。
7. 添加订阅时能从网页发现订阅链接，并跳过重复订阅。
8. OPML 导入保留多层文件夹与嵌套层级，重复 URL 被跳过；导出后可以再次导入。
9. 文件夹最多三级；不同父级可以有同名文件夹，同一父级不能重名；移动文件夹不能产生环或超过三级。
10. 删除文件夹把整棵子树中的订阅移到上一级而不是删除，文章保留；取消订阅删除文章。
11. 配置系统代理或 `HTTPS_PROXY` 后能抓取订阅；本机回环地址不受代理影响。缺少代理时添加订阅会给出可理解的原因。
12. 数据库整理、清理旧文章与设置持久化不会破坏现有数据。
